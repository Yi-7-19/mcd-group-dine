# 验证方法与边界

## 可复现本地检查

```sh
node --test tests/*.test.mjs
node scripts/check-release.mjs
node src/cli.mjs examples/demo.json --out examples/demo-report.html
```

自动测试覆盖金额守恒、共享餐品、费用规则、全额优惠、逐人超预算、缺失预算、无效金额、错误来源元数据、不同预算/门店候选拒绝、HTML 转义，以及 Skill 单独复制后运行。随机分摊样本使用固定种子，验证 1000 组整数金额分摊。

发布检查核实必需文件、配置占位符与官方声明的字节哈希。声明的 Git Blob SHA-1 为 `136e76f3160317049f19f5ba03f4d0fedd70fc3c`，来自官方活动仓库。凭证模式扫描只覆盖常见 Token/私钥格式，仍需人工检查公开文件。

Skill 已使用创建工具附带的 `quick_validate.py` 校验；校验通过证明结构和命名符合检查要求，不证明业务调用成功。

## 页面与交互

当前界面已升级为带图片的响应式账单卡片，并完成一体品牌光标、移动汇总折叠与排版精修，不再依赖横向滚动餐品表。52 项 Node 测试通过，其中包括将 Skill 单独复制到临时目录后生成带四张有效 WebP 和内置 Remotion 的离线 HTML。

本地 Chrome 独立测试配置检查 320、375、768、1024、1440 像素宽度及 812×375 手机横屏，未见页面横向溢出，所有可见主要点击区至少 44px。当前62项浏览器检查通过，额外覆盖全部可点击元素的品牌光标级联、强制颜色回退、手机费用明细的键盘展开，以及导航后同屏阅读两张成员卡。浏览器结果与逐项需求核对见 [UI_UPGRADE.md](UI_UPGRADE.md)。桌面、手机、明细展开、复制异常截图均经过人工查看。

检查覆盖实际 Remotion 中间帧、结束后无持续动画帧循环、减少动态效果的首次打开及运行时切换、真实复制成功、加载状态、权限拒绝后的手动复制、键盘 Enter/Tab、打印展开与状态恢复、图片懒加载和文字对比度。测试不等同于完整 WCAG 认证，也未验证实体手机、Safari、Firefox 或真实打印机。

`node scripts/check-release.mjs` 还校验四张图片和动效构建文件的 SHA-256、Remotion 来源版本、源文件是否同步，以及 50KB 动效体积上限。普通运行不需要安装构建依赖。

## 实际业务调用

真实 WorkBuddy 联调另见 [live-validation.md](live-validation.md)，以该文件明确列出的工具调用及成功结果为准。模拟测试和排版检查不能替代实时接口验证。

本次未测试外送地址、复杂换配、多券叠加、预约、下单和支付；本 Skill 也不会自动执行下单或收款。

## 归一化语义复核

真实响应没有优惠和附加费用，不能用它证明非零优惠或外送费用的字段语义。因此适配器对非零优惠要求宿主显式确认 `discountSemantics`，费用字段要求显式传入 `feeFields`。未知或不守恒的金额会被拒绝，优惠/费用的合成边界用例仅验证本地计算。
