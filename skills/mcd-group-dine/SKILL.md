# 麦麦同桌

把「三个人一起吃，每人预算不同」转成一份能追溯餐品归属和官方报价的拼单账单。

## 收集本单信息

确认成员昵称、每人预算、餐品/口味/不吃什么、共享餐品归属，以及城市或公共地点、门店和到店/外送方式。缺少影响查询的信息时集中询问。不要擅自添加凑单餐品、付费会员卡或替换忌口餐品。可用 a/b/c 等 ID，不需要真名、手机号或同伴账号。

本 Skill 是由一个账号组织一笔订单，不创建邀请链接、不跨账号共享或合并优惠券、不收款。`party-*` 工具服务于派对等主题活动，不能当作多人餐品拼单工具。

## 使用真实 MCP

服务地址为 `https://mcp.mcd.cn`，使用宿主客户端已经连接的麦当劳 MCP。先检查当前工具 schema；不要根据文档猜参数，也不要读取或抄出客户端 Token。缺少连接时说明无法进行实时试算，允许用户明确选择离线演示。

1. 用 `now-time-info` 获取时间。到店场景用 `query-nearby-stores` 查用户提供的公共地点，确认门店；外送场景按宿主的实际 schema 查询可配送门店，须先征得用户使用其配送信息的授权。
2. 用 `query-meals` 读该门店菜单。套餐或换配需用 `query-meal-detail` 核对完整组成和必选项。保留商品编码与实际数量，不从图片或其他门店猜价格。
3. 用户希望用券时，查询本账号当前门店的 `query-store-coupons`，仅考虑返回说明允许的搭配。不要把“券面优惠”相加当作整单优惠，不假设多券可叠加，不调用领券或兑换工具。
4. 保持本组的餐品偏好、数量、门店、就餐方式一致，对无券方案和可行券方案分别调用 `calculate-price`。用户允许餐品替换时才增加替换方案。最多试算 5 个有依据的候选，优先满足每个人预算，再比较本批候选总价。无可行方案时，指出谁超预算并征求具体调整；不强行宣称“最优”或“最低价”。

对当前宿主已验证的参数规则，读 [references/mcp-workflow.md](references/mcp-workflow.md)。价格单位、接口字段仍以当次 schema 和实际结果为准。

## 归一化与分账

逐一把真实报价映射到 [references/input-contract.md](references/input-contract.md)；缺少金额明细时回查，不补造数据。餐品小计应是已经计入该行优惠的官方行金额；整单优惠字段只填尚未计入各行的额外优惠，避免重复扣减。费用必须包含返回的配送、包装等全部附加金额。

如果套餐或整单只能取得一个总额，且不能可靠拆解到餐品，则把整单餐品合成一个共享行，先让成员确认分享权重，清楚标注按共享权重分摊，不能伪称按各人餐品实际金额精算。

运行本 Skill 随附的 `node <本Skill目录>/scripts/cli.mjs <本地归一化报价.json> --out <账单.html>`。完整仓库也可从根目录执行 `node src/cli.mjs`。无需安装第三方依赖，运行环境为 Node.js 20 或更新版本。有多个候选时输入 `{"plans":[...]}`，完整比较结果可输出 `.json`。没有代码执行能力的宿主可以按同样规则列出人工复核表，但不能声称执行过程序。

规则：餐品按归属/共享权重分摊；整单优惠按各人餐品金额比例分摊；费用默认全员均摊，也可经全员选择改为金额比例。金额全程为整数分。共享行、优惠和费用均用最大余数法，余数相同按成员 ID 顺序补齐。全部个人应付之和必须与官方应付一致；不一致就停止生成并核对明细。

## 交付与后续

HTML 报告自带红黄品牌视觉、食物示意图、Remotion 动效、复制和打印功能，可离线打开，不需要宿主另外安装页面依赖。不得将 AI 配图当作官方商品摄影或据此推断价格；图片说明和非官方声明应保留。第三方代码说明见 [references/THIRD_PARTY_NOTICES.md](references/THIRD_PARTY_NOTICES.md)。

给出门店、就餐方式、报价时间、餐品归属、整单总额、每人应付、优惠和费用分摊、每人预算状态以及推荐依据。告知这是一份试算账单，报价可能随门店、时间和优惠变化。

本 Skill 到试算和分账结束。用户另行要求下单时，重新核价并展示完整订单，按其明确授权执行后续流程；不能把“帮我拼单”理解成允许创建订单、扣积分或付款。不得在群聊、公开仓库或截图中透露私人地址、账号信息、券码、凭证或付款链接。
